# A2.6 — Ordonnanceur : experts et tête

> **Statut** : partiel · **Priorité** : P2 · **Programme** : A · **Dépend de** : A2
> **Ligne de roadmap** : A2.6 · **Fiche de résultat** :
> [`placement-kv-8k`](../../../reports/rapport-placement-kv-8k.md).
> **Résumé** : chaque opérateur là où son flux coûte le moins cher — et **seulement** là où
> la qualité le permet.

## Le besoin

Le placement n'est pas un choix de confort : un opérateur mal placé paie le flux à chaque
passe. La règle doit dire, pour un opérateur, **où il tient** et **ce qu'il coûte** — et
refuser une place qui coûte la qualité. Aujourd'hui la règle existe pour le KV ; les experts
et la tête ne sont pas encore ordonnancés.

## L'état

**Partiel** — `drave-core/src/placement.rs` porte les **bandes mesurées**, `cout`,
`classement`, `kv_en_vram` et la règle générale `choisir` : le moins cher **où ça tient**.
Le **KV l'applique** : à 8 k, **×1,93 / ×5,8** ([fiche](../../../reports/rapport-placement-kv-8k.md)).
La **tête** a été essayée par la règle puis **revertée** : le 4 bits y coûte **+10 % de PPL** — la
place n'est pas la qualité. Le **18/11**, deux objets de plus sont entrés dans la règle, **mesurés** :
la **tête** en Q8_0/Q6_K (perte 0, format du fichier — `rapport-a2.6-tete-q8.md`) et les **experts**
(bande **7,0 Go/s par lecteur**, saturation à 8 ; coût, **refus nommé**, **trace** —
`rapport-a2.6-bande-experts.md`), avec **14 tests** et la porte `porte-a2.6-experts`. **Restent** :
le **branchement** des deux dans `model.rs` (opt-in, le défaut ne bouge pas) et la consolidation des
trois tables de bandes de `materiel.rs`.

## Le contrat

| élément | contenu |
|---|---|
| **entrée** | un opérateur (couche, tête, expert, KV), sa taille, les bandes disponibles |
| **sortie** | un placement (support + précision) ou un refus nommé |
| **coût** | le flux de l'opérateur sur son support, par passe |
| **trace** | le classement et le coût retenu sont imprimés et testés |

## Portes

1. la règle choisit **le moins cher où ça tient** (4 tests existants) ;
2. une place qui coûte plus que le budget de perte est **refusée** (la tête) ;
3. le placement est **reproductible** (mêmes entrées, même choix).

## Contrôles négatifs

- forcer la tête en 4 bits : la PPL doit **dégrader** (+10 %) — c'est le refus ;
- un opérateur qui ne tient nulle part : **refus nommé**, pas de placement silencieux ;
- une bande saturée : le choix doit changer, pas échouer en silence.

## Ce qui pourrait le rendre faux

- les bandes sont mesurées sur **cette** machine ;
- le coût d'un flux n'est pas sa latence réelle (le débit ne compte pas) ;
- les experts ne sont pas encore mesurés comme objets.

## Étapes

1. ✅ la règle `choisir` et ses tests ; le KV l'applique ;
2. ✅ la tête essayée (refusée : +10 % de PPL) ;
3. ✅ experts : bande mesurée (7,0 Go/s), coût, refus nommé, trace, 5 tests, porte dédiée ;
4. ✅ tête : Q8_0/Q6_K à perte 0 (14 tests placement) ;
5. ⏳ **brancher** les deux dans `model.rs` (opt-in `DRAVE_PERTE_MAX`, le défaut ne bouge pas).

## Le branchement, mode d'emploi (relevé le 19/11)

Le travail restant est **localisé** et ses entrées existent déjà dans le code :

| site | ce qu'il faut | ce qui existe |
|---|---|---|
| `model.rs` ~4956-4972 (cache VRAM des experts) | les octets d'experts **par jeton** | `gguf::octets_tensor(&TensorInfo)` (l. 1093) + `g.tensor("blk.N.ffn_{gate,up,down}_exps.weight")` ; `cfg.n_expert` / `cfg.n_expert_used` |
| `model.rs` ~4978 | la VRAM libre | `libre_vram` (calculé là, `Materiel::detecter`) |
| `model.rs` ~4988 (tête) | la tête dans son format | `placement::choisir_tete` + `precision_tete` (déjà écrits, testés) |
| `materiel.rs` (plan) | une seule table de bandes | `placement::BANDE_*` (les trois tables de `materiel.rs` y délèguent) |

Le helper à écrire (~15 lignes) : `octets_experts_par_jeton(g, cfg, n_layer)` = somme des trois
tenseurs `ffn_*_exps` de chaque couche × `n_expert_used / n_expert`. Sur le 30B, il doit rendre
**1,097 Go** (la mesure de la bande) — c'est son **test** (avec la trace `1.10 Go/jeton · 6.99 Go/s ·
156.9 ms`, déjà testée).

Le branchement est **opt-in** : sous `DRAVE_PERTE_MAX` (déjà dans `VARS_LUES`), la règle **trace** et
**choisit** ; le défaut ne bouge pas. Portes à relancer : `porte-flux`, `porte-pont`, `porte-coupe`,
`porte-echange-experts`, `porte-a2.6-experts`, `cargo test`. Le risque est le **chemin de
chargement**, pas la taille du diff.
