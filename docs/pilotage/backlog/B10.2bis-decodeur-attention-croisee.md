# B10.2bis — Décodeur à attention croisée

> **Statut** : spécifiée · **Priorité** : P2 · **Programme** : B · **Dépend de** : —
> **Contraint par** : B10.2 négatif (chrF **12,7 / 5,3** contre un plancher **39,6**)
> **Ligne de roadmap** : B10.3 attend cette fiche · **Fiche de résultat attendue** :
> `rapport-b102bis-decodeur.md` (à créer dans `reports/`)
> **Résumé** : faire remonter un décodeur au-dessus du plancher chrF, pour que `z` puisse être
> restitué — et que raisonner sur `z` ait un sens.
> **Glossaire** : [chrF](../../theorie/glossaire/entrees/chrf.md) · [contrôle négatif](../../theorie/glossaire/entrees/controle-negatif.md).

## Le besoin

L'encodeur **converge** (rappel 0,426 contre 0,167 de hasard) mais le décodeur **ne restitue
pas** (chrF 12,7 / 5,3 contre 39,6). Tant que `z` n'est pas restituable, raisonner dessus
mesurerait la surface : c'est le négatif de B10.2, et c'est pour cela que **B10.3** est
bloqué. Ce travail est le déblocage — il n'existait nulle part, il est nommé ici.

## Le contrat

| élément | contenu |
|---|---|
| **entrée** | `z` (l'embedding sémantique de l'encodeur) et la cible texte |
| **sortie** | une restitution décodée, avec son chrF et sa fidélité |
| **coût** | 20–30 articles, **3 graines** ; entraînement sur le GPU |
| **trace** | l'appariement encodeur/décodeur et la graine sont versionnés |

## Ce qui est mesuré

- **chrF** de la restitution, contre le plancher **39,6** ;
- la **fidélité** (le sens restitué, pas la surface) ;
- la **stabilité** sur 3 graines (le résultat ne doit pas être une graine).

## Portes

1. chrF **> 39,6** sur un jeu **tenu à l'écart** ;
2. les **3 graines** dépassent le plancher ;
3. le **même** `z` donne la même restitution (rejeu).

## Contrôles négatifs

- **cibles mélangées** : le chrF doit s'effondrer ;
- **copie de surface** : la sortie ne doit pas être le texte d'entrée ;
- **encodeur gelé** contre encodeur réentraîné : le gain doit venir du décodeur.

## Ce qui pourrait le rendre faux

- **20–30 articles** est petit : le décodeur peut mémoriser ;
- le corpus ONU (en/fr/es) est **parallèle** mais administratif : un seul registre ;
- le chrF peut monter par des **n-grammes de surface** sans fidélité ;
- l'attention croisée ajoute des paramètres : le gain peut venir de la capacité, pas du
  mécanisme — il faut un contrôle à paramètres égaux.

## Étapes

1. choisir et vérifier le corpus (ONU en/fr/es, 20–30 articles, tenu à l'écart) ;
2. brancher l'attention croisée sur `z` (encodeur gelé puis ajusté) ;
3. mesurer 3 graines, les contrôles, et écrire la fiche ;
4. débloquer **B10.3** et **R52** si la porte passe ; sinon, nommer la raison.
