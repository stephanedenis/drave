# B10.2bis — Décodeur à attention croisée

> **Statut** : mesurée · **Priorité** : P2 · **Programme** : B · **Dépend de** : —
> **Contraint par** : B10.2 négatif (chrF **12,7 / 5,3** contre un plancher **39,6**)
> **Ligne de roadmap** : B10.3 attend cette fiche · **Fiche de résultat** :
> [`rapport-b102bis-decodeur.md`](../../../reports/rapport-b102bis-decodeur.md)
> **Résumé** : faire remonter un décodeur au-dessus du plancher chrF, pour que `z` puisse être
> restitué — et que raisonner sur `z` ait un sens.
> **Glossaire** : [chrF](../../theorie/glossaire/entrees/chrf.md) · [contrôle négatif](../../theorie/glossaire/entrees/controle-negatif.md).

## Le besoin

L'encodeur **converge** (rappel 0,426 contre 0,167 de hasard) mais le décodeur **ne restitue
pas** (chrF 12,7 / 5,3 contre 39,6). Tant que `z` n'est pas restituable, raisonner dessus
mesurerait la surface : c'est le négatif de B10.2, et c'est pour cela que **B10.3** est
bloqué. Ce travail est le déblocage — il n'existait nulle part, il est nommé ici.

## Le contrat

| élément | contenu |
|---|---|
| **entrée** | `z` (l'embedding sémantique de l'encodeur) et la cible texte |
| **sortie** | une restitution décodée, avec son chrF et sa fidélité |
| **coût** | 20–30 articles, **3 graines** ; entraînement sur le GPU |
| **trace** | l'appariement encodeur/décodeur et la graine sont versionnés |

## L'état

**Mesurée le 2026-10-29 — négative.** Trois bras (projection, **attention croisée**, segments), **3 graines**, 600 pas : chrF de traduction **11.13 / 11.2 / 11.0** (reconstruction **17.4 / 16.4 / 16.97**) contre un plancher de **38.5**. L'écart entre bras est de **0.2 point** ; il en manque **27.3** pour franchir le plancher. L'attention croisée ne fait pas mieux que la projection : **le plancher du décodeur n'est pas un problème d'attention**. Fiche : [`rapport-b102bis-decodeur.md`](../../../reports/rapport-b102bis-decodeur.md).

**Contrôle de durée** : à **1800 pas**, la traduction reste entre 10,2 et 11,4 sur les deux bras (le rappel monte à 0,40) — ce n'est pas la durée d'entraînement.

**Levier corpus** (2026-10-29) : corpus **JW** (139 unités parallèles, **12 langues**, 5 articles) —
traduction **7,6 / 6,3 / 8,0** contre un plancher de **17,1** ; la reconstruction (eng → eng)
est à **9,4** pour un plancher de 37,8. Le corpus n'est pas le levier non plus. Fiche :
[`rapport-b102bis-corpus-jw.md`](../../../reports/rapport-b102bis-corpus-jw.md).

**Levier capacité** (2026-10-29) : base **31,77 M** (3,4× la base de référence) — traduction
**11,8 / 11,6 / 11,7** (plancher 38,5), reconstruction 16,9 / 16,5 / 17,7. Le gain est de
**0,5 à 0,7 point**, pas les 27 manquants. Fiche :
[`rapport-b102bis-capacite.md`](../../../reports/rapport-b102bis-capacite.md).

**Levier objectif** (2026-10-30) : le même `z` **gelé**, décodé en **mots** (vocabulaire appris
sur l'entraînement, 2 couches d'attention croisée), atteint **32,5** de chrF (plancher 33,7)
contre **11,1** pour le décodeur octet — mais le contrôle **`z` mélangé** ne tombe qu'à
**29,9** : le `z` ne porte que **2,6 points**. Le décodeur est levé, le **verrou est
l'encodeur**. Fiche : [`rapport-b10-decodeur-mots.md`](../../../reports/rapport-b10-decodeur-mots.md).

**Objectif mot sur JW** (2026-10-30) : le même décodeur, encodeur JW gelé — **26,7** de chrF
contre un plancher de **17,1** (+9,5 ; le décodeur octet était à 7,6) ; `z` mélangé **24,8**
(**−1,9**). Le décodeur mot **bat le plancher** sur un corpus non formulaire ; le `z` ne
porte toujours que ~2 points. Fiche :
[`rapport-b10-mots-jw.md`](../../../reports/rapport-b10-mots-jw.md).

## Ce qui est mesuré

- **chrF** de la restitution, contre le plancher **39,6** ;
- la **fidélité** (le sens restitué, pas la surface) ;
- la **stabilité** sur 3 graines (le résultat ne doit pas être une graine).

## Portes

1. chrF **> 39,6** sur un jeu **tenu à l'écart** ;
2. les **3 graines** dépassent le plancher ;
3. le **même** `z` donne la même restitution (rejeu).

## Contrôles négatifs

- **cibles mélangées** : le chrF doit s'effondrer ;
- **copie de surface** : la sortie ne doit pas être le texte d'entrée ;
- **encodeur gelé** contre encodeur réentraîné : le gain doit venir du décodeur.

## Ce qui pourrait le rendre faux

- **20–30 articles** est petit : le décodeur peut mémoriser ;
- le corpus ONU (en/fr/es) est **parallèle** mais administratif : un seul registre ;
- le chrF peut monter par des **n-grammes de surface** sans fidélité ;
- l'attention croisée ajoute des paramètres : le gain peut venir de la capacité, pas du
  mécanisme — il faut un contrôle à paramètres égaux.

## Étapes

1. ✅ vérifier le corpus (UDHR, 30 articles, 10 langues, 24/6 par article) ;
2. ✅ brancher l'attention croisée (et les segments) sur `z` ;
3. ✅ mesurer 3 bras × 3 graines, les contrôles, et écrire la fiche ;
4. ✅ nommer la raison : **l'attention n'était pas le levier** — capacité (9,29 M), corpus
   (30 articles) ou objectif de décodage (byte-level) restent les hypothèses.

## Prochain

**B10.2bis est close** : cinq leviers testés — attention, pas, corpus, capacité (quatre
négatifs) et **objectif** (positif : le décodeur mot fait 32,5 sur UDHR et **26,7 sur JW, au-dessus
du plancher de 17,1** ; mais le `z` ne porte que **1,9 à 2,6 points** sur les deux corpus). Le
suivant est l'**encodeur**, pas le décodeur.

**Le levier suivant n'est pas l'attention** : mesurer la **capacité** (modèle plus grand),
le **corpus** (plus d'articles) ou l'**objectif** (décodage non byte-level) — un à la fois,
même protocole, 3 graines.
